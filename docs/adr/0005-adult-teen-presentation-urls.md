# ADR-0005: Separate Adult and Teen presentation URLs

Status: Accepted
Date: 2026-10-02
Owner approval: approved 2026-10-02.
Amended: 2026-10-03 — canonical route syntax settled before M5 (#47).
Amended: 2026-10-04 — Owner-approved edition-specific discovery routes and neutral-entry semantics (ADR-0009 / #63).

## Context

Five Minutes has one underlying lesson identity with Adult and Teen presentations. The two presentations may have substantially different titles, descriptions, examples and body text.

Using one URL for both presentations creates ambiguity for document metadata, sharing, search indexing and non-JavaScript behaviour. Selecting the edition dynamically on the server would introduce runtime and cache complexity solely to avoid distinct URLs.

The edition-delivery choice also affects the rendering benchmark because two presentation URLs can produce approximately two HTML pages per lesson when both editions exist.

## Decision

Use one canonical lesson identity with separate presentation URLs for Adult and Teen editions.

Canonical lesson-presentation paths use lower-case, slash-less routes: `/adult/<slug>` and `/teen/<slug>`. Edition-specific discovery uses the reserved `/editions/<edition>/...` namespace generated by the same application URL generator: `/editions/adult/library`, `/editions/teen/library`, and `/editions/<edition>/topics/<topic>`. `/adult/library` and similar paths are forbidden because they collide with the lesson-slug namespace. ADR-0009 D1 is the complete discovery-route contract, including edition Library pagination, Topics index/topic/subtopic routes and the neutral chooser/forwarding counterparts. The application URL generator owns all of this syntax. Static-host adapters must serve their generated artifact consistently with these canonical paths rather than changing the application contract to match provider defaults.

The semantic contract is:

- an explicit Adult URL renders the Adult presentation;
- an explicit Teen URL renders the Teen presentation;
- browser-local edition preference may improve navigation but never changes the meaning of an explicit URL;
- there is no default edition: on a first visit, `/` remains the neutral Today page exposing both editions; choosing one there is the global edition selector and stores that preference;
- neutral `/library` and `/topics` entry points route a returning reader to the corresponding `/editions/<saved-edition>/...` URL while preserving query and hash; without saved preference they render a simple Adult/Teen chooser and do not default;
- Search remains the single `/search` URL with an edition setting that initially uses saved preference when available and otherwise requires/retains an explicit reader choice;
- an edition-specific URL always renders the edition named by that URL, including after browser restoration;
- only the global edition selector writes preference. On a lesson page it both writes preference and navigates to the same immutable lesson in the selected edition. Explicit/shared lesson navigation and a visually distinct “Read the other version” link never write preference;
- the selector reflects the edition of the page currently open. If browser storage is unavailable, it still navigates and quietly explains that the choice will not be remembered;
- neutral pages re-check saved preference when restored from browser cache;
- edition switches use normal history entries; they do not replace history;
- lesson Return is an ordinary generated link, never a browser-Back action: it targets the last Library, Topics or Search page visited in the current browsing session, otherwise Today;
- both Adult and Teen presentations are required for publication;
- drafts on branches may be temporarily incomplete while generation is in progress, but incomplete lessons are not publication-eligible and generate no production routes;
- Adult and Teen presentations share lesson identity, publication metadata, taxonomy, provenance and relationships;
- search/catalogue representations are edition-aware;
- Saved/Read state is keyed by immutable lesson identity, not slug or presentation URL, so editions do not become separate saved lessons.

A request for the same canonical path with a trailing slash should normalize to the slash-less form at the hosting boundary. Historical aliases may accept both slash forms but redirect to the slash-less canonical destination. Appropriate canonical/alternate metadata between presentations will be defined during routing/SEO implementation.

## Alternatives considered

### One URL containing both presentations

Rejected as the target model because it makes edition-specific metadata and sharing ambiguous, sends unnecessary content to readers, and makes the non-JavaScript representation less clear.

### One URL with dynamic server-side edition selection

Rejected because it introduces runtime/caching complexity and makes the URL itself insufficient to identify the shared presentation.

## Consequences

- Each edition has correct HTML metadata and a meaningful shareable URL.
- The architecture remains compatible with fully static rendering.
- The number of generated lesson pages may approach twice the number of lesson identities, so rendering/file-count benchmarks must model this decision explicitly.
- The lesson schema must separate immutable identity from mutable slug and model Adult/Teen presentations explicitly.
- Local reader state must use immutable lesson IDs.
- Search and catalogue generation must respect the selected edition.
- With Astro's current directory-style static output, slash-less canonical paths require each hosting adapter to provide equivalent URL handling. Cloudflare does this with `drop-trailing-slash`; `astro preview` deliberately follows Astro's `trailingSlash: 'never'` behavior and returns 404 for a non-canonical trailing-slash lesson request rather than Cloudflare's normalization redirect. A file-style build is a possible future alternative if adapter-specific normalization becomes undesirable.
- Cloudflare's normalization redirect is 307 (provider behavior, not an application contract). Canonical/alternate metadata and 404 `noindex` handling remain bounded SEO follow-up work.

## Follow-up

The two-presentation rendering benchmark has been completed and is reflected in ADR-0002. Canonical route syntax was settled by #47 before M5; canonical/alternate metadata remains bounded SEO implementation work.
