# ADR-0014: positioned lesson visuals and static artwork derivatives

Status: Proposed for independent review. Implements the visual foundation accepted in #188; does not activate weekly publication.

## Decision

Keep schemaVersion 2 and add a backwards-compatible presentation extension, `figures`: one to three mappings with `id`, `role` and `figure`. Each inner figure uses the existing validated types. IDs are unique bounded tokens (20 characters); roles are `lead`, `explanation` and `evidence`. A lead must be a raster; at most one is allowed. Every collection member requires `afterParagraph` in 1–50, checked against actual top-level prose by the loader. Sort by that original paragraph position, preserving array order on ties. Reject simultaneous singular `figure` and plural `figures`, unknown fields, invalid roles and duplicate IDs. The singular field and its desktop layout remain supported unchanged; collections use an inline sequence so several figures cannot overlap in a sticky sidebar.

The 23 October 2026 opt-in `opening: answer-first` extension in [ADR-0006](0006-lesson-schema-and-identity.md) requires the single raster lead after paragraph 1, before any other figure at that anchor. The existing takeaway follows that lead once. All other figures retain their original prose-paragraph anchors; the extra application-rendered section never increments those indices. This changes neither the three-source ceiling nor derivative/provenance rules and does not opt in existing lessons.

Allow up to three distinct local authored PNG/WebP sources, 500 KiB each, 2400 pixels per edge, four million pixels each and 1500 KiB in aggregate (three times the per-source ceiling). The same source may be reused without a second rights record or duplicate byte accounting. Require exact per-source rights coverage, now up to three records. The guard accepts old slug-owned names and bounded `<slug>[-rYYYYMMDD]-v<token>.png|webp` names. Replacements add a new file; existing blobs remain immutable. Revision reuse stays limited to sources already referenced by that same lesson. Both API and local submission adapters collect every referenced source. Preserve all base/head, identity, queue, date, review and file-mode protections; no candidate code execution or raw lesson SVG.

The build emits two derivatives for each designated lead: a 480×320 WebP thumbnail (120 KiB ceiling) and a 1200×630 PNG or JPEG share image (500 KiB ceiling). These are static application endpoints enumerated from the validated catalogue, not reader-time processing. Content hashes in paths prevent stale content. Prefer PNG when it fits; otherwise use metadata-stripped JPEG. Share images contain the whole artwork on ivory rather than risk clipping its subject; thumbnails also contain/pad the entire source, including square or portrait leads. Arbitrary crop instructions and overlays are deferred. Legacy/text-only sharing uses a font-free application-owned clock emblem with a pinned output hash. It emits only a share image; text cards have no unused fallback thumbnail. Without SITE_URL, no fallback image or absolute sharing metadata is emitted.

Use a direct, pinned `sharp` 0.35.5 dependency, already present transitively through Astro in the base lockfile, for deterministic raster processing. Decode both source and output; verify dimensions, format, byte bounds and absence of EXIF/XMP/IPTC/ICC metadata. Authored JPEG is still rejected. Derivatives inherit source provenance and do not consume authored-image or generation slots. Static integrity checks resolve derivative image references; normal delivery file counting includes their outputs. No paid API, database or runtime service is added.

Library cards and the featured card consume the designated lead. Canonical lesson pages receive Open Graph/Twitter title, description, URL, image, MIME, dimensions and alternative text. Redirect/noindex pages receive no article sharing metadata. `SITE_URL` is the only origin source. With no value, canonical links and Open Graph/Twitter metadata remain absent and the sitemap retains its explicit absent-origin marker. CI builds both cases, using a reserved test origin for the configured case. Analytics and feedback remain public/indexable; their shared utility-page registry supplies footer links, page indexing and sitemap entries. No canonical route path or ownership changes.

The Cloudflare adapter prepares an ignored configuration beside its template, deriving both API allowed hostnames from SITE_URL. Production deployment fails without SITE_URL; previews retain their empty overrides and cannot inherit production bindings. The template contains no deployed origin. Changing host, DNS and permanent redirects remains an explicit deployment action, documented in OPERATIONS; reader state need not migrate across origins.

Style artwork lives under docs/visuals/references. The browser fixture source and its derivatives are emitted through test-only static endpoints when the existing fixture-build flag is present. Normal builds reject leaked fixture pages/assets.

## Evidence and limits

See [the proposed style kit and setup evidence](../visuals/style-kit.md). One interactive generation produced the reference artwork and accessible local bytes. The scheduled trial independently passed generation, local bytes, optimisation, current-main validation and Git submission; see its linked ledger. Its centre crop failed the composition criterion; deterministic contain padding preserves the frame. A failed or unavailable stage blocks autonomous artwork activation; it never selects a paid fallback. The Publisher stays disabled.

Tests cover hostile collections, guard parity, three sources/rights, stable placement, derivative decoding/formats/bounds, legacy fallback and cross-theme/mobile/no-script rendering. The browser fixture is build-only; its synthetic diagram is renderer test data, not the proposed scientific treatment. Actual optical diagrams and species fidelity still need the pilot's complete source and visual review. External social networks may cache or ignore metadata; local validation does not guarantee their preview choice.

## Alternatives

A single slot would constrain the pilot. Arbitrary SVG or executable embeds would create a larger trust boundary. Per-request image APIs would add cost and runtime dependencies. Defer those options. This foundation supports original deterministic diagrams exported to reviewed raster files when existing application diagram types do not fit; it does not require generic boxes and arrows.
