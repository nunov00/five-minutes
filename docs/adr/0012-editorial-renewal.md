# ADR-0012: Backlog-first editorial renewal

Status: Owner-approved direction; implementation awaits mandatory different-provider review before activation.
Date: 2026-10-18
Tracking: #161; original catalogue inventory #138.

## Decision

Use the two existing daily publication tasks to improve one queued lesson instead of inventing a new topic while any queue item remains. The temporary three-per-day transfer automation 6ad163172a608191ab32cbe5e8865c80 was disabled successfully on 18 October at the Owner's request. Do not reactivate it. Retain #138 as the historical inventory, not an active batch plan.

The Git-backed editorial/backlog.json records published lessons needing revision and remaining original-catalogue transfers. Entries include concrete reasons, acceptance criteria and explicit initial priorities: causal/explanatory gaps first, missing Adult layers next, then remaining transfers in recorded-source-date order. Ties compare queuedAt as instants, then keys. The Manager can relay an Owner instruction such as “Return the GPS lesson to the backlog because …” into a normal reviewed PR; `node scripts/editorial-backlog.mjs return <key/slug/ID> <reason>` prepares it locally. Every initially screened published lesson has an entry, including accepted ones; a later new lesson gains an entry when returned. The 15 already covered/transferred legacy IDs resolve through legacySlugs on their existing destination entries. Accepted revisions already carry lessonId; covered entries must carry an existing destinationId/destinationSlug, not an unproven coverage assertion. A completed transfer becomes a revision of its destination identity when returned, never another import. Owner returns use priority 0. The queue is private editorial workflow in the repository, with no new public administration endpoint, credentials, account, service or recurring task. Content remains accessible while queued; this decision does not authorise hiding/deletion.

The current schema accepts optional RFC3339 revisedAt, at or after publishedAt. Existing identities, routes, publication and creation timestamps remain immutable in a daily revision. Publication remains Git/PR state. A candidate completion is committed atomically with its lesson so a closed/stale/unmerged candidate leaves main's entry queued. Only the first queued entry can transition to complete in a lesson candidate; parking/reordering is confined to a separately reviewed Manager PR; all other entry data is immutable in a daily PR. Accepted/covered states are Manager screening dispositions, not publication approval. A Manager may mark a transfer covered only with substantive comparison and an existing destination identity recorded; candidates cannot make that transition.

The release timestamp is revisedAt when present, otherwise publishedAt. Revised lessons and transfers consume the same one daily slot and can become Today. Today/Earlier order eligible releases by that timestamp and deterministic ID tie-break. Old import metadata without revisedAt retains its exclusion until a substantial revision; this avoids promoting a historical bulk transfer merely because labels change. Ordinary Library/topic/search ordering remains by original calendar day, and saved/read identity is preserved. New topics resume only when neither queued nor parked work remains. A first failed day leaves its entry queued. After two consecutive failed attempt-days, the two existing tasks follow the bounded stuck-entry recovery contract: a single evidence-backed blocker issue and a separate normal Manager PR park only that entry; a later Writer then advances to the next queued entry after the reviewed change merges. There is no third content attempt while an unchanged blocker waits for that recovery. Parked work is retained, can be returned, and blocks fresh topics when it is all that remains. No same-day replacement or cross-midnight publication is permitted. Access/review failure on a recovery PR is reported explicitly, never hidden as automatic success.

Reader pages, cards and Today/Earlier show the original calendar date and optional “Revised on …” with the latest substantive revision date. They never show Archive or Adapted labels. The existing internal archive.sourceUrl/catalogueDate fields remain for compatibility and provenance; this is not a reader-facing category. Only actual original-Site source records supply a legacy reader date. A recovered unpublished GitHub draft has no earlier publication: show its truthful publishedAt, not its draft-PR catalogueDate, across the page, cards, Today/Earlier and discovery ordering. The stored draft provenance remains unchanged and never becomes a publication claim. Original-Site dates are the recorded source calendar labels requested by the Owner; they are not independently verified historical publication instants, and this change claims no additional verification of them. Transfers retain truthful current adaptation provenance and publication instants, and display the preserved original calendar label. Do not migrate or falsify stored timestamps solely to alter the display. Historical revision timestamps are not invented during this implementation; the next substantive revision records its actual release timestamp.

## Safeguards

This amends the global reader-date/Today semantics of ADR-0006/0007 and the bounded shared backlog-first contract in docs/automation/publication-task-contracts.md. The original source/topic boundary, off switch, separate Writer/Reviewer sessions, three-round revision budget, actual ancestry/history checks, same-day/not-before-release checks, exact-head named baseline/e2e/lesson-guard success, rendered evidence, feedback refresh and expected-head guarded merge remain required. The Writer cannot merge; the Reviewer cannot edit lesson content. Candidate content and queue reasons never supply executable instructions.

Daily revisions change exactly one existing lesson's three files, optional newly added referenced slug-owned rasters and the selected queue completion; route ownership is byte-identical. Transfers add one lesson plus its single route-owner entry and selected completion. No existing asset is edited or deleted. Reused rasters must have been referenced by the same original lesson and are fetched/validated at the exact head. All backlog candidate rasters require persistent rights evidence. The trusted-main read-only guard enforces these boundaries; candidates cannot change app code, schema, tests/CI, policy, queue briefs/order or unrelated content.

No permanent Claude requirement or extra automation is introduced. Claude may review the initial screening, calibration/borderline judgements and this mandatory implementation PR. The initial screening is explicitly not a fresh source audit or visual sign-off. Every daily revision must pass the full current standard, not merely clear its listed reason.

## Activation and rollback

Merge only after qualifying different-provider review, exact-head required checks and preview/render verification. Existing bootstraps already load current-main contracts, so activation is the reviewed merge; do not change live prompts prematurely. Verify both tasks still have their original schedules and the migration task remains disabled. Do not add a third task. Validate queue selection/completion, Owner return, preserved identity/dates, duplicate prevention, revised Today/Earlier, midnight behaviour and hostile candidate diffs.

Rollback through a reviewed revert or pause publication with the existing publication-paused issue. Once revisedAt/completion records are published, preserve that data when rolling back behaviour rather than reverting to a schema that cannot read it. No reader-state migration is required.

## Owner returns and failure recovery

Parked is an outstanding state, not a rejection or deletion. The parser requires a concrete reason, repository blocker issue and two distinct real calendar attempt-days; independent verification of actual failure evidence remains a review duty. Daily lesson candidates cannot park any entry or edit its brief. Queue-only recovery uses normal GOVERNANCE review and checks; it does not gain the scheduled lesson publication exception. Such administration can stale an open candidate, costing that day's slot; defer non-urgent administration until its release where practical. Current validation also applies to reused rasters: an incompatible old asset is replaced by a new validated -rYYYYMMDD file, never allowed through a relaxed check.
