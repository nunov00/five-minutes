# M6.1 production experience foundation

Task: #65. Implements accepted ADR-0005 and ADR-0009 D1–D3. The isolated design prototype is reference material only; no prototype routes, fixtures, state key or script is part of this implementation.

## Routes and progressive enhancement

Today `/` renders both presentations for progressive enhancement but visibly presents one edition across the card, Earlier links and Surprise Me. It honours a valid saved preference and otherwise defaults to Adult without writing that fallback to storage. Its labelled segmented header selector switches Today in place and writes preference. The Adult/Teen links on neutral Library/Topics choosers are also global edition selection surfaces and write preference. Explicit Adult/Teen lesson paths stay unchanged. The plain Read action and ordinary lesson links do not write preference. Lesson pages use the header selector without a duplicate same-lesson switch or visible edition label.

Library and Topics render static edition pages under `/editions/<edition>`. Their complete current route family is generated by `src/lib/urls.ts`; Library pagination is identical by lesson identity across editions. Neutral Library/page and Topics/topic paths remain static chooser pages. With a valid saved preference, enhancement forwards to the equivalent edition route with `location.replace()`, retaining query/hash. The same check runs on pageshow for browser restoration. Without preference, JavaScript or usable storage, the chooser remains usable and neither edition is selected by default.

Search remains `/search`. A valid URL edition setting takes precedence over saved preference; otherwise saved preference selects the search edition, with Adult as the unstored fallback. The global header selector is the sole edition control, saves preference and navigates normally while preserving query/hash. URL query/context is retained for sharing, reload and Return. Existing lazy index ranking, stale-request protection and retry behaviour are retained.

## Versioned local state

The storage adapter is `src/lib/reader/state.ts`. The production key is `five-minutes.reader-state`; its JSON envelope is:

```json
{"version":2,"edition":null,"saved":[],"read":{},"recent":[],"appearance":"system"}
```

- `edition`: null, adult or teen.
- `saved`: unique entries containing immutable lesson UUID `id` and exact presentation `edition`.
- `read`: immutable lesson UUID → ISO date/time string.
- `recent`: entries with immutable lesson UUID `id`, presentation `edition`, and ISO `visitedAt`.
- `appearance`: system, light or dark.

Version 2 changes Saved from identity-only values to exact presentation entries. Valid version 1 entries migrate to the saved preference, or Adult when no valid preference exists; extensions and all other fields are retained. Unknown versions, corrupt JSON or invalid field values are not overwritten. Blocked reads/writes and quota errors are caught. If preference cannot be saved, selection still navigates with a quiet non-persistence note. A one-use session notice handles write failures; no notice marker is added to shareable URLs. Unavailable reader storage is also detected directly at the destination. Unreadable data has a distinct message and a collapsed, explicit reset action that warns it will discard all local reader fields; nothing is reset automatically. If both session notice storage and reader writes fail while reader reads still succeed, the current page can show the notice but the destination cannot carry it. No state is sent to a server.

## Session Return and history

The last supported Library, Topics or Search location is recorded separately in sessionStorage under `five-minutes.session-origin.v1`, as `{version:1,path}`. The Return validator permits only same-origin supported discovery routes, generated page ranges and populated topic tokens; it rejects external URLs, lessons, invalid editions and malformed paths. Query/hash are retained. Search query changes refresh the session origin.

Lesson Return is an ordinary link to that validated session location, otherwise Today. It never calls browser Back. The no-JavaScript/blocked-session fallback is Today. Today’s in-place edition switch keeps `/` and does not add a history entry; edition switches on Search, lessons and scoped discovery pages navigate normally. Choosing from a neutral Library/Topics chooser completes the initial handoff with replacement history, like automatic preference forwarding, so Back does not bounce forward again. Without JavaScript selector and chooser links use normal browser history and neutral pages never auto-forward. Neutral forwarding replaces its own history entry so Back can reach the previous real page. Explicit edition URLs are never restored over by a preference.

## SEO, shell and scope

Edition Library preserves M5 Surprise Me, constrained to the page’s edition and without writing preference. The 404 surface has no canonical and is noindex; its edition choices open Search with an explicit edition.

Neutral discovery choosers use `noindex,follow` and have no edition-content canonical. The sitemap includes Today, Search, explicit lesson URLs and edition-specific discovery pages. Edition pages use their own canonical URL only when SITE_URL is configured; no fictional production origin is emitted. Static completeness checks exclude explicitly noindex surfaces from the sitemap expectation while still checking their links and PWA navigation.

A shared header holds a visibly labelled segmented edition selector. Mobile has labelled Today/Library/Topics/Search navigation; future Saved/preferences UI remains M6.3. Edition tokens differentiate Adult serif/green from Teen sans/purple with system fonts and OS dark mode. Shared control placement and existing essential reading remain consistent.

M6.2 figures/activities/recall changes, M6.3 reader surfaces, ratings, feedback, advertising, accounts and services are outside this task. The PWA identity/start/scope stay `/` and no service worker is introduced.

## Verification boundary

Unit tests cover the envelope, preservation, invalid/future state, blocked storage, generated routes and Return validation. Browser journeys cover preference writers/non-writers, forwarding and replacement history, explicit routes, session Return, Search context, storage denial, neutral restoration events and no-JavaScript use on desktop/mobile Chromium. A dispatched persisted pageshow event verifies the handler but does not prove actual Safari back-forward-cache restoration. Physical Safari, installed-app cold launch and screen-reader verification remain M6.4 integration checks. The exact final commit requires independent different-provider review before merge.

Local implementation checks: zero diagnostics, 110 unit tests and 72 desktop/mobile browser journeys pass. Static verification was run with a configured test origin (including sitemap completeness) and with no production origin configured. Redirect/capacity/file-count gates pass. Twenty-one phone/desktop captures at 320, 390 and 1440 CSS pixels show no horizontal overflow; representative Library and lesson captures were inspected. This evidence uses Chromium, not physical Safari or screen readers.

ADR-0014 retains SITE_URL as the only origin input. With no value, canonical and Open Graph/Twitter metadata are absent and the sitemap carries its absent-origin marker. Configured deployments emit absolute metadata and a populated sitemap; CI verifies both builds. The utility-page registry also supplies analytics/feedback sitemap eligibility; their indexable status is unchanged.
