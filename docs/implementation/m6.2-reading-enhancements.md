# M6.2 reading enhancements

Issue #67, stage B. This PR depends on the schema-v2 corpus migration (PR #68) landing first, as required by ADR-0006. Neither stage merges before independent different-provider review of its exact final head. This implements the accepted ADR-0009 reading contracts, without introducing a service, dependency or persistent answer state.

## Authoring contract

All fields below are optional presentation front matter. Unknown fields/types are rejected, including arbitrary component names. The existing safe Markdown parser and HTML allow-list are unchanged. Text is escaped by application components; figure/activity fields are bounded plain text, not Markdown or HTML.

An app-owned explanatory diagram:

```yaml
figure:
  type: seasons-orbit
  data: { tiltDegrees: 23.4 }
  afterParagraph: 1
  alt: Earth keeps the same axis direction; north faces the Sun in June and south in December.
  caption: Earth's axis keeps pointing towards nearly the same place in space throughout its orbit.
  description: In June the Northern Hemisphere tilts towards the Sun, receiving more direct sunlight and longer days. In December the Southern Hemisphere does. The drawing is schematic, not to scale.
```

The closed app-owned diagram vocabulary is:

- `seasons-orbit`: `data.tiltDegrees` is 23.4 or rounded 23.5;
- `process-flow`: `data.style` is the vetted `filter-reclaim` visual and `data.steps` contains exactly four ordered `{ label, detail? }` stages;
- `cycle-flow`: `data.style` is either `feedback-loop` or `heat-transfer`, with exactly four concise stages around the app-owned cycle artwork;
- `comparison-bars`: `data.style` is `doubling-growth`; `data.items` contains 2–6 `{ label, value, display }` entries and optional plain-text `unit`. Values are finite, non-negative and bounded; at least one is positive.

Step labels, details, comparison labels/display values and units are bounded plain text. Labels must be unique after whitespace/case normalisation. The style allow-list is also a quality boundary: an automated lesson may select a suitable reviewed treatment but cannot invent a generic layout. If no style fits the explanatory relationship, omit the figure. The application owns all markup, arrows, geometry and styling. Content cannot supply paths, drawing commands, CSS, SVG, HTML, links, scripts or animation. Adult and Teen share the mechanism and may use edition-appropriate wording. A new diagram type or style still requires reviewed application code, schema validation and hostile-input/browser coverage.

Alternatively, a reviewed repository-local raster:

```yaml
figure:
  type: image
  src: /lesson-media/reviewed-example.png
  width: 800
  height: 600
  afterParagraph: 1
  alt: A concise alternative to the image.
  caption: A factual caption.
  description: A complete plain-text explanation of the visual mechanism.
```

Place the corresponding file under `public/lesson-media/`. This example describes the contract; it is not a shipped asset. Only lowercase hyphenated filenames and PNG/WebP are supported. Remote URLs, SVG, traversal, encoded paths, nested paths and symlinks are rejected. Maximum: 500 KiB per file, 2400 pixels per dimension and 4 million pixels. The loader checks the container/signature, non-animation, intrinsic dimensions and declared dimensions. It does not decode the image pixels or verify PNG CRCs: editorial review must inspect the actual rendered asset. Deployment capacity remains a separate adapter gate. No raster assets are added by this PR.

All figure types require `alt` (max 200 characters), `caption` (240) and `description` (900). `afterParagraph` defaults to 1 and must refer to an existing top-level prose paragraph, from 1 to 50. The safe parser's paragraph HTML is split without rewriting or re-sanitising it. On mobile the figure appears at that point in the text; desktop puts it alongside the same prose. The full description is a native reveal, available without JavaScript. The lesson must remain comprehensible without the figure.

Teen-only activity:

```yaml
activity:
  prompt: It's January. Which hemisphere is having summer?
  options:
    - The Northern Hemisphere
    - The Southern Hemisphere
  answer: 1
  explanation: The Southern Hemisphere tilts towards the Sun in January. The hemispheres have opposite seasons.
```

`answer` is a zero-based index. Prompt max 140 characters; 2–4 unique options, max 80 each; explanation max 400. Choices are compared ignoring case and redundant whitespace. The prompt must differ from the recall question. Adult activity fields fail validation. Editorial review verifies the correct answer, plausible alternatives, explanation and edition suitability; numerical validation alone is not a factual review.

## Reading behaviour

- The optional Teen module is a collapsed native **What do you think?** reveal before the body. With JavaScript, an unnumbered labelled radio group has 44 px rows. Selection reveals the explanation and announces the selected option. Answers remain in memory only; no storage, scoring, tracking or edition writes.
- Initialisation and `pageshow` reset the selection and close both activity reveals. `autocomplete="off"` provides a second browser-restoration safeguard. Reload/Back tests and simulated restoration cover Chromium; actual Safari back-forward caching remains an M6.4 device check.
- Without JavaScript, plain unnumbered choices and a separate native explanation reveal remain usable. Instruction text matches each mode.
- Every lesson ends its prose with the recall question. The answer and takeaway are inside the same native reveal, so neither appears before the reader attempts recall. Further reading and cross-edition navigation keep their existing contracts.
- Goodhart's law has no figure in either edition. Its Teen activity demonstrates that optional prompts do not require a diagram. No decorative per-lesson image policy is introduced.
- Feedback control, heat pumps, kidney filtration and exponential growth exercise the reusable cycle, process and comparison renderers in both editions. Their diagrams restate reviewed lesson claims and do not introduce new sources.

## Editorial evidence for independent review

The prose, existing recall answers, lesson IDs and URLs are unchanged. Seasons receives a figure in both editions and a Teen January question. Goodhart receives a Teen book-count prediction. Source-access metadata is updated only for the sources checked below; review approval is not fabricated in provenance.

Primary sources checked on 2026-10-04:

- [NASA Space Place: What causes the seasons?](https://spaceplace.nasa.gov/seasons/en/) supports persistent axis direction, opposite seasons, sunlight angle/day length and January's Southern Hemisphere summer.
- [NASA Earth facts](https://science.nasa.gov/earth/facts/) supports the 23.4° tilt and hemisphere-dependent heating.
- [Manheim and Garrabrant, Categorizing Variants of Goodhart's Law](https://arxiv.org/abs/1803.04585) supports the proxy/goal problem. The book example is an illustrative scenario, not a claim about a measured study.

The diagram uses the same north-axis vector in June and December; the equator is perpendicular to that vector. June's Sun lies on the northward side; December's Sun on the southward side. Parallel ray arrows point from each Sun towards Earth. Distances, Earth/Sun sizes and time separation are schematic; the diagram explicitly says not to scale. Independent review must check geometry, every label/caption/description and both activities against these sources.

## Verification and limits

Unit checks cover extension validation, every structured type, hostile/unknown fields, edition restrictions, paragraph placement, raster containers/dimensions/limits and filesystem boundaries. The lesson guard independently accepts only the app-owned structured types and rejects raster, arbitrary or executable figure input. Browser journeys cover each reusable renderer, recall order, keyboard radios, non-persistence, reload/Back/reset, no-JavaScript reading, 320/393/1440 widths, light/dark, forced colours, reduced motion and 200% text size. Static integrity checks the ending of every canonical generated lesson, rather than sampling the whole corpus in browser tests.

The header, preference storage, edition routing, query/Return behaviour and PWA contracts remain M6.1's implementation. No Saved/Read feature is added (M6.3). No real iPhone/Safari, installed-app launch or screen-reader verification is claimed: those remain M6.4, alongside production-scale performance. Device fonts are still system fonts. Diagram labels are SVG text, with an accessible full-text equivalent; enlarging text does not turn the SVG into independent flowing prose.
