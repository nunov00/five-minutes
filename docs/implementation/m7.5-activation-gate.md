## Repository protection

Active ruleset **Protect main** (ID `24837817`) targets `~DEFAULT_BRANCH`. A fresh authenticated read after PR #102 merged recorded:

- enforcement `active`;
- deletion protection;
- non-fast-forward updates blocked;
- Pull Requests required with approving-review count 0;
- strict required checks `baseline`, `e2e` and `lesson-guard`;
- no bypass actors;
- `current_user_can_bypass: never`;
- permitted merge methods `merge`, `squash` and `rebase`.

This prevents force pushes and deletion of `main`, applies the named checks to the shared Owner/admin identity and avoids an approval-count rule that the shared identity could not satisfy. The ruleset API is the authoritative configured mechanism; the integration cannot read the legacy branch-protection endpoint.

The pre-activation main commit had successful `baseline`, `e2e`, Cloudflare Workers Build and branch-cleanup results. The M7.5 Pull Request must independently receive successful `baseline`, `e2e` and `lesson-guard` on its exact final head before merge.

## Activation procedure

Activation is allowed only in this order:

1. Obtain a cumulative different-provider review of M7.3, M7.4, this M7.5 evidence and the resulting system on the exact final Pull Request head.
2. Resolve every BLOCKER and IMPORTANT under GOVERNANCE section 9. Re-review material remediation as required.
3. Require successful exact-head `baseline`, `e2e` and `lesson-guard`; verify the checks actually ran.
4. Record readiness and merge with an expected-head SHA guard under the standing Owner authorisation.
5. Re-read current-main policy and verify the merged evidence commit and active protection.
6. Enable the Writer and Reviewer tasks without changing their prompts, schedules or timezone.
7. Re-read both task records and record the activation time, IDs, exact configuration and enabled state on issue #93.
8. Observe the first live cycle and the first Ready candidate. A run completing without an eligible candidate is not publication success. For the first Ready candidate, record the PR, exact SHA, latest named checks, same-run review, merge method and whether the expected-head merge into protected `main` succeeded. If GitHub or the ruleset refuses it, record the exact refusal and unchanged fail-closed state; do not bypass protection.
9. Open the one-month publication audit issue with a due date before closing #93. The initial due date is 2026-11-12 in Europe/Zurich.
10. Close #93 only after task activation, the audit issue and the first Ready protected-main merge outcome are recorded. Never enable auto-merge.

Merge of this documentation Pull Request alone does not activate publication.
