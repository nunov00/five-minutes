# M6.4 production-experience integration gate

Status: implementation and automated verification in progress under issue #74; physical-device evidence and final review remain required.

## Purpose

M6.4 verifies M6.1–M6.3 as one production experience. It adds no product feature, state field, service worker, backend or dependency. The gate checks the accepted ADR-0005/0009 routing, history and local-state contracts together before M6 is closed.

## Automated evidence

Normal Chromium desktop and iPhone-class journeys remain unchanged. A focused mobile WebKit project now covers the M6 behaviours most likely to differ in Safari:

- neutral chooser replacement and Back behaviour;
- preference re-check when a neutral page is revisited;
- activity/form reset after real Back navigation and reload;
- Save/Read state restoration;
- blocked-storage and no-JavaScript fallbacks;
- appearance persistence, first keyboard focus and 200% text at 320 CSS pixels.

The WebKit project runs only `m6-integration-webkit.spec.ts`; Chromium continues to run the broader suite. Headless Playwright WebKit is supporting engine evidence. It does not prove iOS storage retention, an actual Safari back-forward-cache restore, Add-to-Home-Screen launch behaviour or VoiceOver announcements.

## Physical-iPhone checklist

Run against the Cloudflare preview on a real iPhone before closing the gate. Record iOS version, browser/standalone mode, preview commit and pass/fail notes on the Pull Request.

1. In Safari with site data cleared, open Today. Confirm both editions are offered and no edition is silently selected.
2. Open neutral Library, choose Teen, then use Back once. Confirm it returns to Today rather than bouncing forward.
3. Reopen neutral Library with Teen saved. Confirm it forwards to Teen Library without a visible Adult page; Back still reaches the real previous page.
4. Open a shared Adult lesson while Teen is saved. Confirm the Adult lesson stays Adult, Return is correct and “Read the other version” does not change the saved preference.
5. On the Teen seasons lesson, choose an activity answer, navigate away and Back. Confirm no option or explanation is restored. Reveal Recall and confirm answer plus takeaway open together.
6. Save a lesson, visit Saved, mark the lesson unread/read, select Dark and reload. Confirm state and appearance are consistent and no page scrolls sideways.
7. Increase iPhone text size substantially. Check Today, both seasons lessons, Library, Search and Saved for clipping, obscured controls or horizontal scrolling.
8. Add the preview to the Home Screen, close it fully and launch it cold. Confirm it starts on Today without Safari chrome and all navigation can be completed using in-page controls.
9. With VoiceOver, confirm the skip link is first; edition links announce the current page; Save announces a stable label and pressed state; Read announces “Mark read” or “Mark unread” without a pressed state; activity radio labels and reveal summaries are understandable; status/error messages are announced once.

If a failure is specific to real Safari, standalone mode or VoiceOver, keep M6 open and record an exact reproduction. Do not weaken the check to match the implementation.

## Boundary with M8

M6.4 closes the production-experience and local-reader-state milestone only. Production-scale performance, broader security/accessibility audits, analytics decisions and recovery exercises remain M8 work.
