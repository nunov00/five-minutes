Add at most five genuinely useful new ideas, without a quota, Owner-priority impersonation or duplicates. Do not delete, rewrite, park or mark existing entries complete; retain their immutable details. Change only the ranking/briefs and append new queued ideas with honest Sunday timestamps. The queue's assessedAt remains honest Sunday evidence; after Sunday do not manufacture a Sunday assessment or swap topics.

Set new lesson publishedAt, or existing lesson revisedAt, to **this Friday at 05:00 Europe/Zurich**, preserving original publication/provenance where applicable. This is the intended release time, not a claim that the draft is already published. Record actual creation/review times honestly.

The backlog diff completes only Sunday's first selected entry with that release timestamp and removes its first ranking brief; all other entries/briefs and Sunday assessedAt/summary retain identical JSON serialisation, including key order. `weeklyRemainingPipeline` adds the fixed shortfall explanation only if needed. No daily next-pipeline refresh or new ideas in the lesson PR. A queue/main change that invalidates the fixed selection blocks the candidate. If the Sunday review needs material queue changes that cannot be completed and reviewed on Sunday, record an incomplete selection and skip that cycle; the task cannot fabricate a Sunday reassessment on Monday. ## Friday: verify and publish, or backlog

Friday is a verification/publication stage, not an additional content-review opportunity. No material polishing, new generation, topic replacement or fifth review. Any changed content/head invalidates both receipts; if a necessary fix cannot satisfy every gate in the remaining authorised opportunities, backlog. Do not silently carry assessments over a technical refresh, merge commit or changed main.

The Manager freshly collects the full paginated API evidence: PR/head/base and cumulative diff/blobs via current-main `collectGuardInput` (with real `now`), complete check-runs/workflow runs, authenticated GitHub comment IDs/actors/timestamps plus receipts, and reconciled review-round ledger. Confirm same-repository PR targeting current main, permitted files/history, current-main ancestry, selected Sunday identity, no already-published slot, enabled task and off switch. Invoke trusted current-main `node scripts/weekly-publication.mjs <fresh-manager-snapshot.json>` before merge. Snapshot fields are `prNumber` (the authenticated candidate PR number), `guardInput`, `checks`, `workflowRuns`, `author`, `reviewer`, `rounds`, `published`, `paused`, `enabled`, `now`; author/reviewer records contain API-derived `id`, `authorLogin`, `issueNumber` (derived from the PR endpoint), `createdAt`, `updatedAt`, and parsed `receipt`. Both comments must belong to prNumber, remain unedited (updatedAt equals createdAt), and the author assessment must precede Claude’s review; corrected assessments need a new comment rather than an edit. `rounds` is the actual reserved ordered array of `{round,head}`, not an invented summary; include consumed uncertain rounds and fail if unreconciled. Serialize the API snapshot with JSON.stringify: native Buffer image fields become {type: Buffer, data: byte-array} objects. The CLI restores only those bounded image fields, validating each byte, declared size and aggregate raster budget before structural validation. The helper cannot authenticate caller-supplied JSON or judge prose. Independently verify the API source, provider attribution, checks' applicable guard log, full review/evidence, remaining budgets and all unresolved subsequent feedback. Do not accept a candidate-authored receipt, edited/retracted review or later unresolved finding as approval. Read current comment bodies, edits and all later feedback; numerical receipts alone never grant authority.

Both Codex and Claude must have **lesson quality ≥9**, with a qualifying Ready review, no unresolved BLOCKER/IMPORTANT, source/render passes and exact final candidate SHA. Neither topic appeal, average score, old approval, label nor author self-review can substitute. All four named checks must each have a verified successful completion at that SHA before the author assessment and Claude review. The latest run of each must still be successful at publication; no skip/neutral/pending/failure/spoofed producer. A later successful same-head rerun (for example after marking ready or changing a label) does not invalidate earlier review evidence. Collect complete check history and workflow runs so the helper can prove the earlier successes; missing historical evidence fails closed. Mark ready, wait for any resulting guard run, recollect the snapshot and rerun the helper before the final merge checks. Main must still be the guard's current base. Immediately re-read head/main, pause, task and slot; if any changed/uncertain, stop. Mark the PR ready only when initially eligible, wait for its guard rerun and reconfirm eligibility with the refreshed snapshot, then merge with `expectedHeadSha`, no auto-merge. An uncertain merge response is reconciled against PR/main/production before any further action, never retried blindly.

After merge, verify merged identity and backlog completion on main, successful main checks and actual production deployment, then live canonical route/assets/metadata/render plus home/catalogue discovery and the post-merge reconciliation record under the existing operations contract. A failed deploy is not a successful release: retain one-slot idempotency, report and use reviewed recovery; never create another lesson. Record exact merge/production SHA, URL and evidence on #210. Stop quietly on later duplicate runs only after all post-merge reconciliation is proven.

If either rating is below 9, review is missing, history/budgets/checks/access are uncertain or another gate fails: do not merge. Keep the PR **draft and open**, its branch/commits/assets and all findings; leave the main backlog entry queued/incomplete. Append `backlogged` to #210 and the PR with the pool key, candidate URL/SHA, scores or explicit absence, remaining findings and cumulative counters. This is a workflow outcome, not the backlog schema's unrelated `parked` state (which requires two failed days). Link this carryover evidence in the next Sunday's planning discussion. Do not automatically resume that draft or reset exhausted budgets; re-entry needs a reviewed selection and explicit additional authority if limits were exhausted. New weeks may select other eligible ideas on merit. Never delete/replace the unsuccessful work or mislabel it published/complete.
